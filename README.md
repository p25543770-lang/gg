# Камеры: контуры, режим робота и скелет человека

Приложение показывает рядом изображения с двух камер (например, Logitech C930e). Всё работает на одной вкладке **«Камеры и контуры»**, а обработка выбирается в верхнем списке **«Режим»**:

- **«Фиолетовые контуры»** — выделяет фиолетовым контрастные границы объектов и поверхностей, в том числе видимые края дороги.
- **«Дорога / препятствия»** — оценивает пол/дорогу по нижней части кадра: зелёным подсвечивается предполагаемая проезжая поверхность, красными рамками — контрастные препятствия с номерами треков.
- **«Скелет человека»** — находит людей в кадре и рисует 17 точек тела и соединяющие их линии: голова, плечи, локти, кисти, таз, колени, ступни. Работает для нескольких человек одновременно.

Ползунок **«Чувствительность»** общий для обеих камер: вправо — больше деталей, людей и точек, но больше шума и ложных срабатываний. Работают и другие камеры, поддерживаемые OpenCV.

Вкладки **«Общий вид / панорама»** и **«Стерео / глубина»** удалены из интерфейса. Их модули (`panorama*.py`, `stereo*.py`) остались в исходниках вместе с тестами как задел на будущее, но приложение их больше не загружает и не показывает. Шахматная доска для калибровки по-прежнему лежит в [`calibration/chessboard_9x6_25mm.pdf`](calibration/chessboard_9x6_25mm.pdf).

Это детектор перепадов яркости, эвристика пола/препятствий и оценка позы по одной картинке, а не промышленная система безопасности. Программа может пропустить слабоконтрастные границы, принять тень за препятствие и ошибиться в положении суставов; она зависит от освещения, текстуры и смаза. **Не используйте её как единственный источник данных для управления роботом или обеспечения безопасности.** Нужны независимые бамперы/датчики и аварийный останов.

## Скелет человека

1. В верхнем списке **«Режим»** выберите **«Скелет человека»**. Откройте одну или обе камеры — как обычно, кнопкой «Открыть».
2. Программа находит людей и рисует скелет: зелёные линии — левая половина тела, оранжевые — правая, голубые — плечи и таз. Точки одного человека окрашены одним цветом; у каждого свой номер `#1`, `#2` и своя рамка.
3. Надпись `#2 C 0.69` означает: трек номер 2, человек в центре кадра (`L` — слева, `C` — по центру, `R` — справа), уверенность детектора 0.69. Сверху показывается `PEOPLE: N`, под каждой камерой — «Людей в кадре», время обработки в миллисекундах и активный движок расчёта.
4. Настройки режима появляются под ползунком чувствительности: **«макс. человек в кадре»** (1–8) ограничивает число обрабатываемых людей и экономит время, галочка **«Рамка вокруг человека»** включает и выключает прямоугольник — сам скелет остаётся.
5. Чтобы человек попал в кадр целиком, отойдите на 2–4 метра и следите, чтобы было видно хотя бы плечи и таз. По одним плечам и голове ноги достраиваются ненадёжно.

Как это работает: два небольших ONNX-файла встроены в программу и считаются на процессоре. Сначала **NanoDet-Plus-m** ищет людей, затем **RTMPose-t** считает 17 точек COCO для каждого найденного человека. По умолчанию расчётом занимается **ONNX Runtime** — он примерно втрое быстрее OpenCV DNN. Если ONNX Runtime недоступен, программа автоматически переключается на **OpenCV DNN** и продолжает работать, только медленнее; какой движок используется сейчас, написано под изображением. Интернет, видеокарта и Python не нужны — модели и движок уже внутри `.exe`. Обе модели распространяются по Apache-2.0, подробности и контрольные суммы — в [`models/README.md`](models/README.md).

Производительность и ограничения:

- Скелет считается дольше контуров, но начиная с версии 1.12 запас по скорости есть. Замер на двухъядерном процессоре при кадре 450×340: один человек — около 10 мс на кадр (примерно 100 FPS обработки против 19 FPS в версии 1.11), три человека — около 30 мс (примерно 33 FPS против 10 FPS). Реальная частота ограничена камерой, которая обычно даёт 30 FPS, и числом открытых камер. Кадр не копируется в очередь: всегда обрабатывается самый свежий.
- Что дало ускорение: переход на ONNX Runtime, одна общая сессия модели на обе камеры вместо отдельной на каждую, поиск людей раз в три кадра, декодирование только тех областей, где может быть человек, переиспользуемые буферы нормализации и очищенный от дублей весов граф детектора. Интерфейс также больше не обращается к потоку камеры на каждом тике.
- **Сеть точек тела считается для каждого человека в каждом кадре.** Пропуск «неподвижных» людей был проверен и отклонён: движение кисти почти не заметно на уменьшенном кадре, и скелет визуально замирал бы. Экономия при этом не нужна, так как расчёт и без неё быстрее камеры.
- Детектор людей запускается раз в три кадра, поэтому быстро входящий в кадр человек может появиться с задержкой до двух кадров (примерно 0.07 с при 30 FPS). Между запусками рамки следуют за измеренным движением тела, а точки обновляются каждый кадр и сглаживаются. Точность проверена против покадрового эталона: медианное отклонение точек 2.7 пикселя, в 90% кадров — не более 4.7 пикселя.
- Если строка состояния показывает движок `OpenCV DNN`, значит ONNX Runtime не загрузился. Программа работает, но медленнее; в готовом `.exe` из релизов используется ONNX Runtime.
- Номер трека живёт, пока человек виден. При перекрытии, уходе из кадра или сильном скачке номера могут перепутаться или начаться заново. Номера независимы для левой и правой камеры.
- Это **двумерная оценка позы**, а не измерение. Программа не знает расстояния до человека, не определяет личность, не распознаёт действия и не заменяет датчик безопасности. Смаз, засветка, перекрытия, необычные позы, дети, сидящие и лежащие люди, а также человек частично вне кадра дают заметные ошибки.

## Режим робота и углы установки

1. В верхнем списке **«Режим»** выберите **«Дорога / препятствия»**. Зелёная область — предполагаемый пол/дорога, красные рамки — препятствия; `#1`, `#2` — номера треков в пределах одной камеры. Надпись `CENTER OBSTACLE` означает, что рамка пересекла условный центральный коридор кадра, а не измеренную траекторию робота.
2. Наведите камеры так, чтобы в нижней центральной части кадра обычно был свободный пол: алгоритм берёт оттуда эталон поверхности. Если закрыть эту зону колесом/корпусом или поставить туда препятствие при старте, оценка станет хуже.
3. Для переднего Kinect 360 начните с наклона **15–20° вниз** (диапазон 10–25° допустим). Боковые камеры наклоните вниз на тот же угол, а по горизонтали разверните от оси Kinect примерно на **±45°**: левую на 45° влево, правую на 45° вправо. Это стартовая геометрия, а не универсальный стандарт.
4. Точный разворот зависит от горизонтального поля зрения боковых камер. Kinect 360 имеет около 57° по горизонтали. Чтобы сохранить перекрытие 10–20°, используйте оценку: `угол ≈ 28.5° + половина_поля_зрения_боковой_камеры − перекрытие`. Например, при боковом поле 80° получится примерно 48–58°. При 60° — примерно 38–48°. Начинайте с 45° и проверьте, чтобы на стыках кадров была общая видимая зона пола.
5. Жёстко закрепите камеры, уберите люфт и вибрации. Учтите ближнюю слепую зону: у Kinect 360 надёжная глубина обычно начинается примерно с 0.8 м, поэтому наклон вниз не заменяет ближние датчики.

Ограничения режима робота: он не использует глубину Kinect 360 и не объединяет три камеры в единую 3D-модель. Тени, мокрый/блестящий пол, стекло, низкие препятствия, резкая смена освещения и смаз могут давать пропуски и ложные срабатывания. Номера треков независимы для каждой камеры и могут сбрасываться при потере объекта.

## Готовая версия для Windows (без Python)

1. Откройте [GitHub Releases](../../releases) и скачайте `PurpleCorners.exe` из релиза `purple-corners-v1.14.1` или более нового релиза этой программы. Другие релизы репозитория могут относиться к другим приложениям.
2. Либо откройте [Actions → Windows camera app](../../actions/workflows/windows.yml), выберите успешный запуск для нужной ветки и скачайте артефакт **PurpleCorners-Windows-x64**. Для скачивания артефактов нужен вход в GitHub; артефакты хранятся 90 дней. Распакуйте ZIP.
3. Подключите одну или две камеры, закройте другие программы, использующие их, и дважды щёлкните `PurpleCorners.exe`. Python устанавливать не нужно. При первом запуске распаковка может занять некоторое время.
4. В левой и правой панели выберите разные номера камер (по умолчанию 0 и 1) и выберите разрешение в каждой панели, затем нажмите «Открыть». Чтобы изменить разрешение работающей камеры, выберите значение и нажмите «Применить»: камера перезапустится автоматически, не прерывая вторую камеру. Для работы только с одной камерой вторую панель можно не открывать. Кнопка «Закрыть» отключает соответствующую камеру. Если нужная камера не найдена, попробуйте другие номера: они зависят от порядка устройств в системе. При необходимости разрешите доступ к камере в настройках конфиденциальности Windows. Ползунок чувствительности общий для обеих панелей.

Под каждой камерой отображаются её FPS и два средних времени за последние 30 показанных кадров:

- **В приложении** — от получения кадра из OpenCV до передачи обработанного изображения виджету, включая ожидание в приложении.
- **Чтение** — сколько длился вызов OpenCV для получения кадра. Это часто время ожидания следующего кадра, а не его возраст или полная задержка.

Программа запрашивает выбранное разрешение (по умолчанию 640×480), MJPEG и 30 FPS, считывает камеры независимо и обрабатывает свежие кадры без искусственного ожидания между ними. Доступны 320×240, 640×480, 1280×720 и 1920×1080. Драйвер может не принять выбранное разрешение: фактический размер полученного кадра отображается под панелью вместе с предупреждением, если он отличается. Более высокое разрешение может снизить FPS. Драйвер может также не принять остальные параметры; реальная скорость зависит также от освещения, устройства и пропускной способности USB. Попробуйте подключить камеры к разным USB-контроллерам и улучшить освещение.

Программа не меняет экспозицию камеры. В предыдущих версиях сообщение о том, что режим экспозиции не удалось прочитать, было вызвано ограничением OpenCV/DirectShow. Если в тёмном помещении FPS падает, улучшите освещение или настройте экспозицию в фирменном приложении камеры.

Ни один из показателей не измеряет **полную задержку от съёмки до экрана**: задержки внутри камеры и драйвера до получения кадра и физический вывод на дисплей недоступны приложению.

Сборка предназначена для 64-битной Windows. В Actions проверяются запуск упакованного приложения, интерфейс двух панелей, режим робота, загрузка моделей скелета на тестовом фото и использование ONNX Runtime без реальной камеры; работу с конкретной камерой нужно проверить на своём компьютере. Не подписанный цифровой подписью файл может вызвать предупреждение Windows SmartScreen.

## Сборка на Windows

Установите 64-битный Python 3.12 и выполните в папке проекта:

```bat
py -3.12 -m pip install -r requirements-windows.txt
py -3.12 -m PyInstaller --noconfirm --clean --onefile --windowed --name PurpleCorners --add-data "models;models" --add-data "assets;assets" --collect-binaries onnxruntime --hidden-import onnxruntime app.py
```

Флаги `--add-data` обязательны: без них модели скелета и проверочное фото не попадут внутрь файла, и режим «Скелет человека» сообщит, что модель не найдена. Флаг `--collect-binaries onnxruntime` нужен, чтобы внутрь попал и быстрый движок расчёта; без него программа соберётся, но будет работать медленнее, на OpenCV DNN. Самотест упакованной версии это проверяет и не даёт собрать медленный вариант незаметно. На Linux и macOS разделитель в `--add-data` — двоеточие (`"models:models"`).

Результат — `dist\PurpleCorners.exe`. Python нужен только для сборки, а не для запуска готового файла. Workflow собирает его на Windows при push и pull request, а также запускается вручную через Actions. Для публикации предварительного релиза запустите workflow вручную на нужной ветке и укажите новый тег вида `purple-corners-v1.0.0`; файл добавится в GitHub Releases после успешной проверки. Также релиз публикуется при push с заголовком коммита `release: purple-corners-v1.0.0` (используйте новый тег).

## Запуск из исходного кода

В Windows установите Python 3.10–3.13 с [python.org](https://www.python.org/downloads/), отметив **Add Python to PATH**, затем выполните:

```bat
py -m pip install -r requirements.txt
py app.py
```

На Linux можно запустить `python3 -m pip install -r requirements.txt`, затем `python3 app.py`; может понадобиться системный пакет `python3-tk` и разрешение на доступ к видеоустройству.

Эффект отображается только в окне приложения; виртуальная камера для других приложений не создаётся. Программа запрашивает параметры видеопотока, но не меняет экспозицию.
