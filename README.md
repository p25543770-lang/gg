# Камеры: контуры, стерео и режим робота

Приложение показывает рядом изображения с двух камер (например, Logitech C930e) и выделяет фиолетовым контрастные контуры объектов и поверхностей, в том числе видимые границы дороги. Ползунок «Чувствительность» регулирует количество выделяемых деталей: сдвиг вправо помогает увидеть менее контрастные границы, но добавляет шум. Также работают другие камеры, поддерживаемые OpenCV.

В режиме **«Дорога / препятствия»** программа оценивает пол/дорогу по нижней части кадра: зелёным подсвечивается предполагаемая проезжая поверхность, красными рамками — контрастные препятствия с номерами треков. Это эвристика по цвету/текстуре для одной или двух обычных RGB-камер, а не гарантированное распознавание дороги.

На вкладке «Стерео / глубина» те же две камеры можно использовать как стереопару: после калибровки приложение выравнивает кадры, считает диспаратность алгоритмом SGBM и показывает карту глубины. Клик по карте показывает оценку глубины в точке (медиана области 9×9). Метрическая глубина доступна только при известной базовой линии и единицах измерения; без них показывается диспаратность в пикселях.

Это детектор перепадов яркости, оценочная стереокарта и простая эвристика пола/препятствий, а не промышленная система безопасности: он выделяет и другие объекты, может пропустить слабоконтрастные границы и зависит от освещения, текстуры, синхронизации и калибровки. **Не используйте его как единственный источник данных для управления роботом или обеспечения безопасности.** Нужны независимые бамперы/датчики и аварийный останов.

## Режим робота и углы установки

1. В верхнем списке **«Режим»** выберите **«Дорога / препятствия»**. Зелёная область — предполагаемый пол/дорога, красные рамки — препятствия; `#1`, `#2` — номера треков в пределах одной камеры. Надпись `CENTER OBSTACLE` означает, что рамка пересекла условный центральный коридор кадра, а не измеренную траекторию робота.
2. Наведите камеры так, чтобы в нижней центральной части кадра обычно был свободный пол: алгоритм берёт оттуда эталон поверхности. Если закрыть эту зону колесом/корпусом или поставить туда препятствие при старте, оценка станет хуже.
3. Для переднего Kinect 360 начните с наклона **15–20° вниз** (диапазон 10–25° допустим). Боковые камеры наклоните вниз на тот же угол, а по горизонтали разверните от оси Kinect примерно на **±45°**: левую на 45° влево, правую на 45° вправо. Это стартовая геометрия, а не универсальный стандарт.
4. Точный разворот зависит от горизонтального поля зрения боковых камер. Kinect 360 имеет около 57° по горизонтали. Чтобы сохранить перекрытие 10–20°, используйте оценку: `угол ≈ 28.5° + половина_поля_зрения_боковой_камеры − перекрытие`. Например, при боковом поле 80° получится примерно 48–58°. При 60° — примерно 38–48°. Начинайте с 45° и проверьте, чтобы на стыках кадров была общая видимая зона пола.
5. Жёстко закрепите камеры, уберите люфт и вибрации. Учтите ближнюю слепую зону: у Kinect 360 надёжная глубина обычно начинается примерно с 0.8 м, поэтому наклон вниз не заменяет ближние датчики.

Ограничения режима робота: он не использует глубину Kinect 360 и не объединяет три камеры в единую 3D-модель. Тени, мокрый/блестящий пол, стекло, низкие препятствия, резкая смена освещения и смаз могут давать пропуски и ложные срабатывания. Номера треков независимы для каждой камеры и могут сбрасываться при потере объекта.

## Стереорежим и калибровка

1. Жёстко закрепите обе камеры так, чтобы они смотрели примерно в одну сторону и их поля зрения сильно пересекались. Базовая линия (расстояние между оптическими центрами) должна быть заметной: для настольных сцен обычно начинают с 5–15 см. Не переставляйте камеры и не меняйте фокус/зум после калибровки.
2. На вкладке «Камеры и контуры» откройте левую и правую камеры с одинаковым фактическим разрешением. Номера камер выбираются вручную; левая панель считается левой камерой стереопары.
3. Перейдите на вкладку «Стерео / глубина». Если у вас уже есть калибровка OpenCV, нажмите «Загрузить…» и выберите YAML/JSON. Поддерживаются поля `K1`, `D1`, `K2`, `D2`, `R`, `T`, `image_width`, `image_height` и необязательное `translation_unit` (`m`, `cm`, `mm` или `unknown`). Если единицы `T` неизвестны, выберите их при загрузке; иначе приложение покажет только диспаратность, а не метры.
4. Для новой калибровки возьмите шахматную доску и укажите число **внутренних углов** (например, 9×6, а не число клеток) и сторону клетки в мм. Готовый шаблон: [`calibration/chessboard_9x6_25mm.pdf`](calibration/chessboard_9x6_25mm.pdf) — 9×6 внутренних углов, клетка 25 мм. Печатайте на A4 альбомно в масштабе 100% («Actual size») и проверьте линейкой, что сторона клетки ровно 25 мм. Доска должна целиком помещаться в оба кадра. Нажмите «Снять пару доски», затем измените наклон, расстояние и положение доски. Снимите не менее 10 пар, лучше 15–30, включая углы кадра и разные наклоны. Избегайте бликов, смаза и изгиба доски.
5. Нажмите «Калибровать». После успешного расчёта сохраните файл кнопкой «Сохранить…». Затем включите стерео. Если разрешение камер изменилось, загрузите калибровку для нового разрешения или откалибруйте пару заново.
6. Кликните по карте глубины, чтобы получить оценку в точке. Красный цвет означает меньшую глубину, синий — большую; чёрный — отсутствие надёжных данных. Цветовые пределы «ближе/дальше» меняют только раскраску, а не сами измерения.

Ограничения: синхронизация здесь программная, по времени получения кадров из OpenCV, а не аппаратная. Для быстрых движений нужны аппаратно синхронизированные камеры и короткая выдержка. Слабая текстура, засветки, повторяющиеся узоры, отражения и плохая калибровка дают пропуски и ошибочную глубину. Точность падает с расстоянием: малая базовая линия ухудшает дальнюю глубину, большая — ближнюю и общую область видимости.

## Готовая версия для Windows (без Python)

1. Откройте [GitHub Releases](../../releases) и скачайте `PurpleCorners.exe` из релиза `purple-corners-v1.7.0` или более нового релиза этой программы. Другие релизы репозитория могут относиться к другим приложениям.
2. Либо откройте [Actions → Windows camera app](../../actions/workflows/windows.yml), выберите успешный запуск для нужной ветки и скачайте артефакт **PurpleCorners-Windows-x64**. Для скачивания артефактов нужен вход в GitHub; артефакты хранятся 90 дней. Распакуйте ZIP.
3. Подключите одну или две камеры, закройте другие программы, использующие их, и дважды щёлкните `PurpleCorners.exe`. Python устанавливать не нужно. При первом запуске распаковка может занять некоторое время.
4. В левой и правой панели выберите разные номера камер (по умолчанию 0 и 1) и выберите разрешение в каждой панели, затем нажмите «Открыть». Чтобы изменить разрешение работающей камеры, выберите значение и нажмите «Применить»: камера перезапустится автоматически, не прерывая вторую камеру. Для работы только с одной камерой вторую панель можно не открывать. Кнопка «Закрыть» отключает соответствующую камеру. Если нужная камера не найдена, попробуйте другие номера: они зависят от порядка устройств в системе. При необходимости разрешите доступ к камере в настройках конфиденциальности Windows. Ползунок чувствительности общий для обеих панелей.

Под каждой камерой отображаются её FPS и два средних времени за последние 30 показанных кадров:

- **В приложении** — от получения кадра из OpenCV до передачи обработанного изображения виджету, включая ожидание в приложении.
- **Чтение** — сколько длился вызов OpenCV для получения кадра. Это часто время ожидания следующего кадра, а не его возраст или полная задержка.

Программа запрашивает выбранное разрешение (по умолчанию 640×480), MJPEG и 30 FPS, считывает камеры независимо и обрабатывает свежие кадры без искусственного ожидания между ними. Доступны 320×240, 640×480, 1280×720 и 1920×1080. Драйвер может не принять выбранное разрешение: фактический размер полученного кадра отображается под панелью вместе с предупреждением, если он отличается. Более высокое разрешение может снизить FPS. Драйвер может также не принять остальные параметры; реальная скорость зависит также от освещения, устройства и пропускной способности USB. Попробуйте подключить камеры к разным USB-контроллерам и улучшить освещение.

Программа не меняет экспозицию камеры. В предыдущих версиях сообщение о том, что режим экспозиции не удалось прочитать, было вызвано ограничением OpenCV/DirectShow. Если в тёмном помещении FPS падает, улучшите освещение или настройте экспозицию в фирменном приложении камеры.

Ни один из показателей не измеряет **полную задержку от съёмки до экрана**: задержки внутри камеры и драйвера до получения кадра и физический вывод на дисплей недоступны приложению.

Сборка предназначена для 64-битной Windows. В Actions проверяются запуск упакованного приложения, интерфейс двух панелей и обработка тестовых кадров без реальной камеры; работу с конкретной камерой нужно проверить на своём компьютере. Не подписанный цифровой подписью файл может вызвать предупреждение Windows SmartScreen.

## Сборка на Windows

Установите 64-битный Python 3.12 и выполните в папке проекта:

```bat
py -3.12 -m pip install -r requirements-windows.txt
py -3.12 -m PyInstaller --noconfirm --clean --onefile --windowed --name PurpleCorners app.py
```

Результат — `dist\PurpleCorners.exe`. Python нужен только для сборки, а не для запуска готового файла. Workflow собирает его на Windows при push и pull request, а также запускается вручную через Actions. Для публикации предварительного релиза запустите workflow вручную на нужной ветке и укажите новый тег вида `purple-corners-v1.0.0`; файл добавится в GitHub Releases после успешной проверки. Также релиз публикуется при push с заголовком коммита `release: purple-corners-v1.0.0` (используйте новый тег).

## Запуск из исходного кода

В Windows установите Python 3.10–3.13 с [python.org](https://www.python.org/downloads/), отметив **Add Python to PATH**, затем выполните:

```bat
py -m pip install -r requirements.txt
py app.py
```

На Linux можно запустить `python3 -m pip install -r requirements.txt`, затем `python3 app.py`; может понадобиться системный пакет `python3-tk` и разрешение на доступ к видеоустройству.

Эффект отображается только в окне приложения; виртуальная камера для других приложений не создаётся. Программа запрашивает параметры видеопотока, но не меняет экспозицию.
