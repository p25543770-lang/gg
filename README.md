# Stereo Space

Веб-приложение, которое объединяет два видеопотока с двух физических камер в **один совмещённый живой видеопоток** (режим «Общий вид»). Камеры стоят по бокам и смотрят на одну сцену; приложение находит общие детали, определяет левую и правую камеру, оценивает смещение кадров и строит единый кадр общей сцены: изображения обоих камер геометрически перепроецируются в общий вид, яркость и цвет выравниваются, а в зоне перекрытия выполняется плавный шов. Смещение объектов из-за параллакса компенсируется по оценке глубины там, где она надёжна, — двойные силуэты не рисуются. Области, которые не видит ни одна камера, остаются пустыми и помечаются сеткой — они не заполняются выдуманным содержимым.

Дополнительно приложение строит приблизительные карту глубины и облако точек (отдельный режим «Глубина / 3D»), ищет **хомяка** на кадрах левой камеры и переносит одну рамку на общий вид тем же геометрическим преобразованием, что и изображение. Глубина животного считается по исходной стереопаре, а не по совмещённому кадру. Обработка выполняется локально в браузере (тяжёлые операции — в Web Worker); видео никуда не отправляется. Пока камеры не подключены, отображается помеченная демо-сцена — она не является изображением с камер и не анализируется детектором.

## Windows: приложение `.exe`

Добавлена desktop-оболочка Electron для **Windows 10/11 x64**. Portable-версия запускается двойным щелчком: пользователю не нужны Node.js, npm, отдельный браузер или ручной запуск сервера. При старте portable-файл распаковывает среду Electron во временную папку; это не установщик.

### Сборка (рекомендуется на Windows)

На машине **разработчика** нужны Node.js указанной ниже версии, npm и интернет для первоначальной установки зависимостей и загрузки Electron/инструментов упаковки:

```powershell

npm run test:desktop
npm run build:win
```

Готовый файл после успешной сборки: **`release/Stereo-Space-1.1.0-win-x64.exe`** (версия берётся из `package.json`). Каталог `release/win-unpacked/` — промежуточная распакованная версия; её нельзя распространять как один отдельно скопированный `Stereo Space.exe`. Для передачи одного файла используйте portable `.exe` из корня `release/`.

Также добавлен workflow [Windows portable app](.github/workflows/windows.yml): он собирает приложение на `windows-latest` и прикрепляет `.exe` к запуску GitHub Actions как артефакт **Stereo-Space-Windows-x64**. Для проверки оболочки на машине разработчика: `npm run desktop` (сначала собирает веб-часть, затем открывает Electron).

### Локальная обработка и разрешения

В пакет входят Chromium/Node среды Electron, production-интерфейс, Web Worker, модель `hamster-ssd-mobilenet-v2.onnx`, WebAssembly ONNX Runtime, шрифты и лицензии модели/среды. Модель при запуске не скачивается. Внутренний безопасный адрес `stereo://app/` обслуживает файлы из пакета **без HTTP-сервера и открытого TCP-порта**. Внешние сетевые запросы заблокированы; Electron renderer не имеет доступа к Node.js, работает с sandbox и context isolation. Обновления из интернета не проверяются.

Обработка двух камер, рамка хомяка, положение центра и приблизительная глубина используют прежний код веб-приложения. Камеры включаются кнопкой «Подключить камеры». Оболочка разрешает своему окну только видеокамеры, но не микрофон. В Windows включите **Параметры → Конфиденциальность и безопасность → Камера → Разрешить классическим приложениям доступ к камере** (названия зависят от версии Windows). Закройте другие программы, занимающие камеры. Для запуска готового приложения интернет не нужен. Экспорт `.ply` остаётся через обычное скачивание файла Chromium; настройки сохраняются в профиле Electron отдельно от браузера.

Сборка **не подписана** сертификатом издателя и использует стандартную иконку Electron. Windows SmartScreen может показать предупреждение неизвестного издателя. Для публичного распространения рекомендуется настроить подпись и собственную иконку; не отключайте защиту Windows глобально.

## Запуск веб-версии

Нужны Node.js **22.22.2+ (ветка 22), 24.15+ (ветка 24) или 26+**, npm, современный браузер с WebGL, WebAssembly SIMD и поддержкой двух одновременных видеопотоков (например, актуальный Chrome или Edge).

```bash
npm install
npm run dev
```

Откройте адрес из вывода Vite. Модель (~18 МБ) и среда WebAssembly (~15 МБ до сжатия) поставляются вместе с приложением и загружаются с того же сервера; внешние API для распознавания не используются. После установки зависимостей приложение можно собрать и запускать с локального сервера без интернета, пока этот сервер доступен браузеру. Для доступа к камерам нужен безопасный контекст: `http://localhost` или HTTPS. Обычный HTTP-адрес вида `http://192.168.…` для этого не подходит. В некоторых встроенных окнах предпросмотра доступ к камере ограничен политикой браузера — тогда откройте приложение в отдельной вкладке и разрешите доступ.

## Работа с камерами и «Общий вид»

1. Подключите две **разные** камеры и нажмите «Подключить камеры», затем разрешите доступ к ним. Приложение автоматически выберет два доступных устройства. Если устройств больше, можно выбрать нужные в карточках. Если подключена только одна камера, подключите вторую, обновите список значком рядом с заголовком «Источники» и выберите её в карточке «Камера 02».
2. Расположите камеры **по бокам** от общего поля зрения, на одинаковой высоте и параллельно, направив их на одну хорошо освещённую сцену. Кадры должны перекрываться и содержать заметные общие детали. Изображение не должно быть зеркальным. Лучше использовать камеры с одинаковыми объективами и разрешением; для первой проверки держите сцену неподвижной.
3. Нажмите **«Автонастройка»**. Приложение сопоставляет детали нескольких кадров, определяет левую и правую камеру, измеряет сдвиг кадров по высоте, оценивает перекрытие (процент кадра с общими деталями), качество совпадений и разницу яркости. Чек-лист в панели «Автонастройка» показывает только реально измерённые значения. После успешной настройки сохраняется **профиль** для этой пары устройств и режима съёмки (разрешения): при повторном подключении тех же камер геометрия восстанавливается без повторного замера. Если камеры, разрешение или положение изменились, приложение показывает «Требуется повторная калибровка» и просит запустить «Автонастройку» снова.
4. Если автоматической настройки недостаточно, выберите левую камеру вручную кнопкой «Выбрать стороны вручную» (или поменяйте стороны местами стрелкой). Значение «Не удалось определить стороны» означает, что приложение не угадывает порядок и не выдаёт ложную готовность.
5. В «Геометрии пары» укажите **базу** — измеренное расстояние между **центрами объективов** в сантиметрах. Это единственное физическое измерение, которое нужно приложению; без него расстояния в метрах недостоверны. Угол обзора задаётся для кадра после центрального кадрирования до 4:3. Значения по умолчанию — лишь пример, не измерение вашей установки.
6. Режимы просмотра:
   - **«Общий вид»** — один совмещённый видеопоток общей сцены. Основной режим после успешной настройки. Пока совмещение ненадёжно, здесь показываются исходные потоки и статус настройки, а не фиктивная картинка.
   - **«Две камеры»** — исходные потоки для проверки подключения, перекрытия и калибровки.
   - **«Глубина / 3D»** — карта глубины и облако точек по стереопаре (существовавшие ранее режимы).
   - **«Хомяк»** — кадр анализа с рамкой животного.
7. Статусы общего вида: «Настраиваем», «Общий вид готов», «Недостаточно перекрытия», «Ненадёжная глубина», «Требуется повторная калибровка», «Кадры рассинхронизированы», «Совмещение недоступно». Под ними показываются только реально измеряемые показатели: число совпадений, процент перекрытия, сдвиг по высоте, разница яркости, задержка обработки, частота обновления и рассинхронность потоков. Проценты «точности» не выдумываются.
8. Вращайте облако мышью или касанием, меняйте масштаб колесом/кнопками, скачивайте текущие реальные точки в `.ply`. Экспорт недоступен для демо-сцены. Кнопка отключения останавливает потоки камер и освобождает обработку. Числовые настройки и профиль настройки сохраняются в `localStorage` браузера, видео и облака автоматически не сохраняются.
9. Откройте вкладку **«Хомяк»** или карточку «Наблюдение за хомяком». После определения левой камеры модель загружается и начинает анализировать кадры автоматически. При обнаружении показывается **одна** рамка: на исходном кадре и на общем виде — в координатах общего вида через то же геометрическое преобразование, что применено к изображению. Значение «Не измерено» означает, что для оценки расстояния недостаточно надёжных стереосовпадений — выдуманная точка в пространстве не показывается. Если модель не запустилась, в карточке появится кнопка повторной попытки.

Если камера занята другим приложением, закройте его и попробуйте снова. Не все браузеры и устройства допускают одновременную работу двух камер. Если совпадений мало, проверьте перекрытие кадров, порядок камер, освещение, одинаковую высоту и параллельность; однотонные или повторяющиеся поверхности сопоставляются плохо. Если качественное совмещение невозможно, приложение автоматически показывает исходные потоки с конкретной причиной и советом (увеличить перекрытие, улучшить освещение, закрепить камеры, повторить настройку) — проблема не маскируется размытием или прозрачным наложением.

## Как устроен «Общий вид» и его ограничения

Оба кадра снимаются с центральным кадрированием 4:3 и приводятся к рабочему разрешению (256 × 192; при перегрузке разрешение автоматически снижается до 192 × 144 и 160 × 120 с уведомлением). В Web Worker строится **карта горизонтальных смещений** (disparity) взаимно согласованными совпадениями локальных деталей; только согласованные совпадения считаются измеренными геометрией, случайные совпадения отбрасываются. Оба изображения перепроецируются в **виртуальную камеру посередине** между физическими: пиксель смещается на половину своего смещения (`x_лев − d/2`, `x_прав + d/2`), поэтому близкие и далёкие объекты встают на свои места и не двоятся — в отличие от одной глобальной гомографии. Яркость и цвет правой камеры выравниваются по левой подгонкой по реально совпавшим пикселям, а в зоне перекрытия выполняется плавный переход. Вся область кадра, которую видит хотя бы одна камера, заполняется только реальными пикселями; невидимые области остаются пустыми с пометкой.

Если смещения измерены ненадёжно, сомнительная глубина **не используется** для сильного искажения: пиксели сдвигаются лишь на общее малое смещение, а в зоне перекрытия берётся изображение одной камеры, чтобы не рисовать двойной силуэт. Если согласованных совпадений мало, но они укладываются в плоскую модель, применяется **плоский (панорамный) режим**: правый кадр переводится в систему левой камеры подогнанной по реальным совпадениям гомографией. Этот режим честно помечается в интерфейсе и подходит для плоских сцен; для объёмных сцен близкие объекты в нём могут двоиться. Бесшовный результат для любой сцены не обещается.

Кадры двух камер сопоставляются **программно по времени получения**: в интерфейсе показывается измеренная рассинхронность потоков. Это не аппаратная синхронизация. Если рассинхронность превышает 150 мс, совмещение останавливается (иначе движущиеся объекты удвоились бы), и приложение переходит на исходные потоки со статусом «Кадры рассинхронизированы». Очередь обработки ограничена: устаревшие результаты отбрасываются и не показываются как текущие, измеряются задержка и частота обновления.

Рамка хомяка переносится на общий вид тем же преобразованием, что и изображение (контур из восьми точек следует за локальной глубиной); при ненадёжной геометрии она помечается как приблизительная. Показывается одна рамка одного животного, а не две от наложения потоков. Глубина и 3D-положение животного рассчитываются по **исходной стереопаре** и калибровке, а не по смешанному изображению; при недостоверности выводится «Не измерено».

## Как получается глубина и ограничения

Каждая камера снимается с центральным кадрированием 4:3; для стереосопоставления тот же снимок уменьшается до 256 × 192, после чего в Web Worker ищутся взаимно согласованные совпадения локальных деталей. Детектор использует снимок левой камеры 512 × 384, полученный до уменьшения. Приближённая глубина рассчитывается как `Z = f × B / d`, где `B` — база в метрах, `f` — фокусное расстояние в пикселях, оценённое по введённому горизонтальному углу, а `d` — горизонтальное смещение совпадения. Это глубина вдоль оптической оси, а не расстояние по прямой до точки. Отображаемый диапазон использует 5-й и 95-й процентили найденных глубин.

**Это не полноценная стереокалибровка.** Приложение не определяет внутренние параметры объективов, не исправляет дисторсию и поворот камер полноценной стереоректификацией, не синхронизирует камеры аппаратно и не строит сплошную 3D-модель. Оно лишь оценивает небольшой общий вертикальный сдвиг, когда находит совпадения. Два разных поля зрения, наклон или схождение камер могут привести к неверному автоопределению, отсутствию точек или ошибочной глубине. Для метрически точных измерений и произвольно установленных камер необходима полноценная калибровка стереопары и синхронизация. Результат не следует использовать для задач, критичных к безопасности.

Экспорт `.ply` содержит отдельные точки в метрах: ось X направлена вправо, Y — вверх, камеры смотрят вдоль отрицательной оси Z. Цвет точек соответствует выбранному режиму окраски.

## Распознавание хомяка

Используется локальная модель Google SSD MobileNet V2 Open Images V4 с оставленным классом **Hamster** (не COCO-класс компьютерной мыши), конвертированная в ONNX. Источник, лицензии, контрольные суммы и воспроизведение конвертации описаны в [`public/models/README.md`](public/models/README.md). Модель запускается в том же Web Worker, что и стереосопоставление, через `onnxruntime-web` (WebAssembly, один поток); ни кадры, ни результаты не отправляются на внешний сервис. Модель и WASM предоставляются вместе с приложением, а не скачиваются из CDN.

Распознавание вероятностное: рамка с оценкой класса выше порога 0,25 показывается как «Похоже, хомяк». Если на полном кадре зверёк не найден, дополнительно проверяются до девяти перекрывающихся областей: при ограничении времени поиск продолжается на последующих кадрах, начиная с последней подходящей области. Это помогает при небольшом размере объекта, но может замедлять обновление. Число в процентах — оценка модели, а не проверенная вероятность; возможны как пропуски, так и ложные срабатывания. Сильное размытие, закрытый клеткой зверёк, маленький размер в кадре и плохой свет могут ухудшать результат. Проверяйте работу на своих животных и камерах.

Рамка, снимок и стереоточки относятся к одной обработанной паре кадров, а не к разным моментам; если обработка остановилась, старый результат исчезает через пять секунд. Для глубины берётся медиана взаимно проверенных стереосовпадений в центральной части рамки, если есть не менее восьми точек, распределённых по трём областям, и их глубины достаточно согласованы. Иначе показывается «Не измерено». Это **не сегментация животного**: внутри рамки может быть фон, камеры могут не совпасть по времени, а качество неоткалиброванной стереопары ограничено. Поэтому даже показанная глубина может оказаться неверной. Это глубина вдоль оси левой камеры, не точное расстояние по прямой; она не подходит для измерений, критичных к безопасности.

## Проверка и сборка

```bash
npm test       # стерео, детектор, модель и жизненный цикл с тестовыми потоками
npm run build  # проверка TypeScript и production-сборка в dist/
```

Автоматические проверки используют тестовые кадры и потоки, а не реальные устройства: перед постоянным использованием проверьте работу со своей парой камер, хомяком и освещением.
